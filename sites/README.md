# Шесть лендингов одного продукта

Здесь лежат пять новых сайтов. Шестой, контрольный, - это `topinjector/` в
корне репозитория. Каждый сайт проверяет **свою гипотезу продажи**, а не свой
оттенок кнопки: если после теста вы не сможете сказать, какое утверждение о
покупателе оказалось верным, тест был поставлен зря.

Гипотезы выведены из контентного аудита одиннадцати конкурентов
(`../seo-landings-audit.html`), а не придуманы.

## Что проверяет каждый вариант

| Папка | Бренд | Гипотеза | Дыра рынка, которую закрывает | Порт |
| --- | --- | --- | --- | --- |
| `../topinjector` | TopInjector | скорость плюс возврат остатка | контроль, менять нельзя | 3000 |
| `reestr` | Реестр | проверяемые данные бьют обещание | именных кейсов нет ни у одного из девяти живых сайтов | 3001 |
| `porog` | Порог | отказ повышает доверие | «безопасно» соседствует с «накруткой» у большинства | 3002 |
| `klik` | Клик | считать дают до убеждения | калькулятор у всех в середине страницы, а не в начале | 3003 |
| `rech` | Прямая речь | человек продаёт лучше сервиса | категория анонимна, личный бренд есть у одного | 3004 |
| `razgon` | Разгон | скорость продаёт, если подкреплена расписанием | «топ за три дня» продаёт лучше всего и верят ему меньше всего | 3005 |

Ядро продукта, тарифная логика и гарантия во всех шести одинаковые. Меняется
угол подачи и то, что стоит на первом экране.

## Запуск

Зависимости ставятся один раз на весь репозиторий из корня:

```bash
npm install

npm run dev                    # все шесть сразу, порты 3000-3005
npm run dev:all reestr klik    # только названные
npm run dev:all -- --force     # освободить занятые порты и запустить
npm run dev:stop               # погасить всё, что осталось на 3000-3005

npm run dev:reestr             # по одному: dev:porog, dev:klik, dev:rech, dev:razgon
npm run build:all              # собрать все шесть
```

| Порт | Сайт |
| --- | --- |
| 3000 | topinjector *(контроль)* |
| 3001 | reestr |
| 3002 | porog |
| 3003 | klik |
| 3004 | rech |
| 3005 | razgon |

Вывод шести серверов сведён в один поток и помечен цветным префиксом с именем
сайта. Ctrl+C гасит все сразу, включая дочерние процессы `next`.

**Про зависшие порты.** Обработчик Ctrl+C гасит дерево процессов целиком, но
при жёстком снятии раннера — закрытая вкладка терминала, диспетчер задач,
упавший редактор — сработать он не успевает, и `next` остаётся держать порт.
Следующий запуск тогда откажется стартовать и скажет, какие порты заняты.
Лечится `npm run dev:stop` или сразу `npm run dev:all -- --force`.

Оба скрипта трогают только процессы, в командной строке которых есть путь
этого репозитория: чужой сервер на 3000 от соседнего проекта останется жив.

## Продакшн и запуск на сервере

```bash
npm run build:all              # собрать все шесть
npm run start:all              # запустить собранное, localhost
npm run serve                  # собрать и запустить наружу (0.0.0.0)
```

Раннер один и тот же, режим переключается флагом:

```bash
node scripts/run-all.mjs --mode start --host 0.0.0.0 reestr razgon
```

Без сборки продакшн не стартует и скажет, у каких сайтов её нет: `next start`
падает в этом случае невнятно, поэтому проверка идёт заранее по `.next/BUILD_ID`.

### Чего одного скрипта на сервере не хватит

Скрипт работает на переднем плане: он умрёт вместе с ssh-сессией и не
поднимется после перезагрузки. Для боевого сервера нужны ещё две вещи, обе
лежат в [`deploy/`](../deploy):

- **[`landings.service`](../deploy/landings.service)** — юнит systemd. Держит
  процессы, поднимает после перезагрузки и перезапускает при падении. Внутри
  помечено, что заменить: пользователя и путь к репозиторию.
- **[`nginx.conf.example`](../deploy/nginx.conf.example)** — прокси, который
  раздаёт шесть сайтов по шести доменам. Это не украшение: у каждого варианта
  должен быть свой домен, иначе тест не имеет смысла — посетитель, видящий в
  адресной строке `ip:3003`, не считает страницу сайтом компании.

За nginx хост оставляют `localhost`: тогда порты 3000-3005 не торчат наружу
вовсе, а в интернет смотрят только 80 и 443. `--host 0.0.0.0` нужен, только
если ходить будут прямо в порты — для быстрой проверки с другой машины.

### Что понадобится на сервере

Node.js той же мажорной версии, что и локально, и `npm ci` вместо `npm install`
(ставит ровно то, что записано в корневом `package-lock.json`). Выкатка новой
версии:

```bash
git pull && npm ci && npm run build:all && sudo systemctl restart landings
```

Скрипты кроссплатформенные: остановка на Linux ищет процессы через `ss`, с
откатом на `lsof`, если его нет.

Папки независимы: у каждой свой `package.json`, своя сборка и свой деплой.
Общий workspace нужен только чтобы не держать шесть копий `node_modules`. Если
понадобится вынести сайт в отдельный репозиторий, достаточно скопировать папку
и выполнить в ней `npm install`.

## Схема событий: менять только одновременно во всех шести

Файл `src/lib/analytics.ts` намеренно **продублирован** в каждом сайте, а не
вынесен в общий пакет: сайты деплоятся по отдельности, и общий пакет сделал бы
невозможной выкатку одного сайта без остальных.

Цена дубля - сотня строк. Цена рассинхрона - несравнимые результаты теста,
то есть впустую потраченный трафик. Поэтому правило жёсткое: **имена событий и
набор параметров правятся во всех шести файлах одновременно**.

| Событие | Когда | Параметры |
| --- | --- | --- |
| `hero_view` | первый экран отрисован | — |
| `cta_click` | клик по любой целевой кнопке | `place` |
| `calc_interact` | первое касание калькулятора или анкеты | `widget` |
| `calc_result` | расчёт досчитался (с задержкой 700 мс) | зависит от виджета |
| `pricing_view` | блок цен попал в зону видимости | — |
| `proof_view` | блок доказательств попал в зону видимости | — |
| `faq_open` | раскрыт вопрос | `id`, `q` |
| `contact_click` | клик по телеграму или почте | `channel` |
| `scroll_depth` | прокрутка до 25/50/75/100 % | `depth` |
| `register_outbound` | уход в личный кабинет | `place` |
| `pro_view` | открыта страница для агентств | — |

Каждое событие несёт `variant` из `NEXT_PUBLIC_VARIANT` (задан в `.env` каждого
сайта). События уходят в `window.dataLayer` и, если задан
`NEXT_PUBLIC_YM_ID`, в цель Яндекс.Метрики.

Ключевые метрики сравнения: `hero_view` → `register_outbound` (главная
конверсия), `hero_view` → `calc_interact` (вовлечение), `scroll_depth 75`
(дочитываемость).

## Что обязательно заменить до запуска

Всё перечисленное сейчас демонстрационное. Пометки «демо» и дисклеймеры в
подвалах стоят намеренно - снимать их можно только вместе с заменой данных.

| Что | Где |
| --- | --- |
| Домены, адреса кабинета, телеграм, почта | `src/lib/site.ts` каждого сайта |
| Записи реестра, включая проваленные | `reestr/src/lib/content.ts` |
| Ставки, доли подачи, коэффициенты | `*/src/lib/content.ts` |
| Имя автора, город, стаж, отказы месяца | `rech/src/lib/site.ts` и `content.ts` |
| Портрет автора | `rech/public/portrait.jpg`, см. комментарий в `rech/src/app/page.tsx` |
| Сроки расписания | `razgon/src/lib/content.ts` |

Две вещи, которые нельзя «причесать» при замене данных:

1. **В реестре должны остаться неудачные записи.** Таблица со стопроцентным
   успехом называется рекламным буклетом, и читатель это чувствует. Заменяйте
   демо-неудачи настоящими, а не удаляйте.
2. **Проверка допуска в «Пороге» должна уметь отказать.** Если текст отказа
   начнёт заканчиваться словами «но вы всё равно попробуйте», вариант
   перестанет отличаться от остальных пяти и выпадет из теста.

## Главное правило: механика следует из концепции

Первая сборка провалила именно это. Палитры, шрифты и фактуры у сайтов были
разные, а **грамматика компонентов - одна**: у всех ползунок с живым
пересчётом, у всех `details/summary` с номером и вращающимся плюсом, у всех
прямоугольная кнопка с одинаковыми отступами. Разные шкурки на одном скелете
читаются как машинная работа быстрее, чем одинаковый цвет: кнопку и
калькулятор рассматривают в упор, а фон видят краем глаза.

Сейчас у каждого сайта своя модель взаимодействия, и она выведена из жанра:

| Сайт | Расчёт | Почему так | Вопросы | Кнопка |
| --- | --- | --- | --- | --- |
| Реестр | печатная таблица, ноль интерактива | публикацию читают и распечатывают, у неё не бывает ползунков | сноски, раскрыты всегда | двойная рамка графы бланка |
| Порог | форма с полями и подачей | заявку заполняют и подают, после чего выносится решение - как и весь сайт | пункты регламента, раскрыты | графитовый прямоугольник |
| Клик | ползунки с живым пересчётом | расчёт и есть продукт, это единственный сайт, где ползунок оправдан | аккордеон: панель прибора складывается | белая инверсная плашка |
| Прямая речь | два `select`, вшитых в строку текста | автор считает при вас вслух, приборов в письме не бывает | диалог, реплики через тире | подчёркнутая фраза без коробки |
| Разгон | сегментный переключатель по ступеням | весь сайт стоит на дискретных ступенях суток и скоростей | крупные заголовки в две колонки | алый блок капслоком |

Четыре из пяти блоков вопросов и три из пяти расчётов - серверные компоненты:
без интерактива в браузер не уезжает JavaScript, а текст ответов попадает в
выдачу целиком, а не только в JSON-LD.

**При доработке:** прежде чем добавить ползунок, аккордеон или плашку, найдите
в таблице выше, что уже стоит на этом месте у соседей. Если приём повторяется
на трёх сайтах, он перестал быть приёмом.

## Чего на сайтах нет намеренно

**Возврата денег.** В первой сборке у всех шести стоял раздел «нет сдвига за
семь суток - вернём остаток». Убрано целиком: обещание вернуть деньги в
категории, где деньги обещают вернуть все, не работает как отличие и тянет
разговор в сторону гарантий, которых в этой нише никто дать не может.

Вместо него у каждого сайта своё закрывающее утверждение о контроле:
порядок заведения записи (Реестр), остановка за час пунктом регламента
(Порог), остановка счётчика (Клик), выключатель на стороне клиента (Прямая
речь), стоп-кран на любых сутках (Разгон). Общее в них одно и оно проверяемо:
подача прекращается в течение часа, а неизрасходованный баланс не сгорает.

## Правила оформления, общие для всех шести

- Ни одной карточки с иконкой в скруглённом квадрате. Структуру держат
  линейки, колонки и нумерация.
- Никаких градиентов в сине-фиолетовой гамме, размытий и цветных теней.
- Микровзаимодействия 90-240 мс. Переходы в 300-500 мс - главная причина,
  по которой интерфейс ощущается обычным.
- `ease-in` в интерфейсе не используется: он тормозит ровно в тот момент,
  когда пользователь смотрит внимательнее всего.
- Анимируются только `transform` и `opacity`.
- Ховер только за `@media (hover: hover)`: на тапе он даёт ложные срабатывания.
- Зона нажатия не меньше 44 пикселей независимо от кегля подписи.
- Каждый шрифт проверен на кириллицу. Это не формальность: Space Grotesk,
  Space Mono, Syncopate, Lato, Public Sans, Bebas Neue, Anton, DM Sans -
  всё, что шрифтовые базы предлагают первым делом, кириллицы не имеет вовсе.
- `prefers-reduced-motion` уменьшает движение, а не отключает обратную связь:
  сдвиги и масштабирование уходят, цвет и прозрачность остаются.

## Дизайн-системы

Каждый сайт объявляет свою систему в `src/app/globals.css`, и там же в шапке
файла записано, **почему** она такая и какие запреты нельзя снимать при
доработке. Читайте эти комментарии перед правками: половина решений там
неочевидна и была принята после того, как очевидный вариант не сработал.
